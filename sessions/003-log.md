## Work Log

- Fetched Figma design context for nodes `42:13` (wide layout) and `81:24` (mobile nav) before writing any code.
- **Mobile nav decision:** Figma node `81:24` shows logo + "Get Mad" only on mobile — no hamburger menu. Implemented exactly as designed.
- **Design system gap — nav background:** Figma nav uses dark text on a light parchment background, but no semantic light background token existed. User directed: create a new secondary background token using `--primitive-beige-500`. Added `--color-bg-nav` to `tokens.css` and `DESIGN-SYSTEM.md`.
- **Design system gap — icon colour:** Figma uses `--color/icon/default: #685127` (brorange) for diamond accents, but no semantic token existed. Added `--color-icon-default` to fill the gap and comply with the "no primitive tokens in components" rule.
- Admin files placed in `public/admin/` (not root `admin/`) so Vite copies them to `dist/` on build.
- JS files (`modal.js`, `load-content.js`) initially added as plain `<script src>` tags; Vite warned they couldn't be bundled. Changed to `type="module"` — Vite then bundled all three JS entry points cleanly.
- **Bug found post-session:** `position: sticky` was on `.nav` inside `<header>`. The containing block (`<header>`) was the same height as the nav, so the sticky constraint resolved to zero — the nav would scroll away after 1px. Fixed by moving `position: sticky; top: 0; z-index: 100` to the `header` element.
- **Secondary bug fixed:** Netlify Identity widget was a blocking `<script>` in `<head>`, making an external network request before page render. Added `defer` attribute to remove it from the critical path.
- All four local tests (sticky nav, mobile nav, keyboard focus, modal) confirmed passing after fixes.
- Netlify Identity and Git Gateway enabled in dashboard; end-to-end CMS editorial workflow verified on live site.
- Merged `dev` → `main` via PR #1.
